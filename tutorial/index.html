Assistant

Front end for hs-dev-manager. Pull a client's HubSpot files, edit them locally, send changes back. No terminal commands or menus to learn first, and nothing here gets in the way if you already know them.

Built for developers and anyone comfortable with HTML/CSS Runs on Claude Code Wraps hs-dev-manager (hsdm)
Why this exists

Editing HubSpot directly is risky. Skipping local dev is slow.

Changing templates inside HubSpot leaves no history and no undo. Working locally fixes that, but usually means learning Node, Git, and a new CLI first. This skill removes that step. Tell Claude what you want. It runs hsdm for you and stops before anything reaches a live portal.

Before you start

Five things need to be true first

Say "check my HubSpot setup" and Claude verifies all of this for you. Say "set it up for me" and it installs whatever's missing too, one step at a time. Either way, you don't need to run these yourself. Listed here so you know what "ready" looks like.

  • Node.js 22+24 LTS recommended if installing fresh
  • HubSpot CLI 8.xgives you the official hs commands + login
  • Gittracks every fetch and deploy as a local commit
  • Portal accesspermission to the account and its Design Manager
Sandbox or staging first. Not sure which portal to use? Ask Client Service or the Web Development Manager before Claude connects anything. Don't guess.
!

Nothing goes live without your yes, by name

Before Deploy, before Watch, and before any Overwrite during a conflict, Claude names the exact client and account ID, states what's about to change, and waits for an explicit yes. Every time. Not a "sure, go ahead" from five minutes ago. An answer to that specific question.

Same rule for adding a new portal connection and removing a saved path. Both change shared configuration other people rely on.
Walkthrough

Step by step

The real hsdm screens, and the command that gets you to each one.

1

Say what you want

No syntax to learn. State the outcome. Claude maps it to the right hsdm command.

you  get me the latest files for Cleveland Brothers
claude checking hsdm · portal cleveland-brothers (43414393) · running Fetch…

Also works for: "I need to edit a module for [client]", "what portal am I on", "send my changes live", "stop watching."

2

Pick the portal, by name and ID

HubSpot accounts can share similar names. Claude checks both the account name and the account ID before touching anything. Name alone is never enough.

Select a portal
acme-industries  (11933201)
your-client-name  (50553855 · last used)
+ Add portal (authenticate a new HubSpot account)
3

The main menu: six actions

After you pick a portal, hsdm shows six options: Paths, Fetch, Watch, Lint, Deploy, Deploy history. Claude picks the right one from what you asked for. You don't need to read this menu yourself.

Shown here so the real screen looks familiar.
4

Choose what to work on

Paths are the Design Manager folders tracked locally. Claude adds a new one, browsing HubSpot's folders for you, or picks a saved one. Either way it states what it's about to fetch before pulling anything down.

Removing a saved path only untracks it locally. It never deletes anything from HubSpot.
5

Fetch: pull the latest first

Read-only against HubSpot, so run it often. If HubSpot changed, Claude asks: pull only what changed, or do a full re-download. Uncommitted local edits block the fetch automatically. That's hsdm protecting your work, not a bug.

6

Watch: continuous sync, the highest-risk mode

Watch uploads every saved change to the live portal right away, for as long as it runs. Claude confirms the exact portal first, and checks in if a session runs long. When you stop, it suggests a Deploy so a clean local commit records what went live.

Requires explicit confirmation
7

Deploy: review, then send it live

Claude lists the files about to upload. HubSpot's own lint runs first, then a diff against the last synced state. Each conflict is Skip, Overwrite, or Cancel, one at a time. Every Overwrite gets its own confirmation. A local commit is written the moment the upload succeeds.

Questions

If something feels off

Claude says a menu needs a real interactive terminal. What now?
Some hsdm screens are full-screen interactive prompts that can't always be driven remotely. Claude tells you when this happens and coaches you through it live instead. It states exactly what to expect on screen and asks what you see, so the same confirmation rules still apply.
Fetch says it's blocked. Is that broken?
No. It means you have uncommitted local changes in that portal's files, and hsdm is refusing to overwrite them. Claude helps you review and commit, or intentionally discard with confirmation, before trying again.
I think the wrong thing got deployed. What do I do?
Stop and say so right away. Every successful deploy is a scoped local Git commit, so what shipped is recorded and reviewable. Loop in the Web Development Manager or Client Service immediately rather than trying to quietly fix it.
Do I need to know Git or npm to use this?
No. If you're comfortable editing HTML and CSS but haven't touched Git, npm, or a terminal, Claude handles those parts and explains what's happening as it goes. If you already know them, you can still just say what you want instead of typing it by hand. Either way, you only need to know the outcome: "get the latest files," "send this live," "what portal am I on."
